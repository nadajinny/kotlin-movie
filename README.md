# 3 단계 - 영화 예매(DB)

## 데이터베이스 관련 기능 목록
- [x] 애플리케이션 시작 시 데이터베이스 연결을 생성한다.
- [x] 로컬 실행 환경에서는 파일 기반 H2 데이터베이스를 사용한다.
- [x] 테스트 환경에서는 In-Memory H2 데이터베이스를 사용한다.
- [x] 데이터베이스 초기화 시 필요한 테이블을 생성한다.
- [x] 영화 정보를 데이터베이스에 저장한다.
- [x] 상영관 정보를 데이터베이스에 저장한다.
- [x] 상영 일정을 데이터베이스에 저장한다.
- [x] 예매 정보를 데이터베이스에 저장한다.
- [x] 애플리케이션 재실행 시 저장된 영화 및 상영 정보를 다시 조회한다.
- [x] 애플리케이션 재실행 시 저장된 예매 정보를 반영해 좌석 예약 상태를 복원한다.
- [x] 최초 실행 시 상영 정보가 비어 있으면 기본 데이터를 seed 한다.
- [x] 결제 확정 이후에만 예매 정보를 데이터베이스에 저장한다.

## 데이터베이스 테스트 목록
- [x] H2 데이터베이스 연결이 정상적으로 생성된다.
- [x] 테이블 초기화가 정상적으로 수행된다.
- [ ] 기본 상영 데이터를 저장한 뒤 다시 조회할 수 있다.
- [ ] 예매 정보를 저장한 뒤 다시 조회할 수 있다.
- [ ] 저장된 예매 정보가 좌석 예약 상태에 반영된다.
- [ ] 테스트 간 데이터가 서로 영향을 주지 않는다.

## 구현 전략
### 1. 저장 대상
- 상영 정보와 예매 정보를 데이터베이스에 저장한다.
- 좌석 배치는 고정 규칙으로 관리하고, 좌석 자체를 테이블로 따로 저장하지 않는다.
- 실제 영속 대상은 `Movie`, `Screen`, `ScreeningSchedule`, `ReservationInfo`에 필요한 정보다.

### 2. 스키마 구성
- `movies`: 영화 ID, 제목, 러닝타임
- `screens`: 상영관 ID
- `screenings`: 상영 ID, 영화 ID, 상영관 ID, 시작 시각
- `reservations`: 예매 ID, 상영 ID, 좌석 행, 좌석 열

### 3. 도메인 복원 방식
- 데이터베이스 조회 결과를 바로 비즈니스 로직에 넘기지 않고, 도메인 객체로 다시 조립한다.
- 좌석은 고정 좌석 템플릿을 기준으로 생성하고, 예매된 좌석만 `RESERVED` 상태로 복원한다.
- 이 방식으로 도메인 객체 변경을 최소화한다.

### 4. 계층 분리
- `persistence/db`: JDBC 연결, 설정, 스키마 초기화
- `persistence/repository`: 상영 정보 및 예매 정보 저장/조회
- `persistence/seed`: 기본 상영 데이터와 고정 좌석 배치
- `persistence/CinemaDatabase`: 애플리케이션이 사용하는 DB 진입점

### 5. 구현 순서
1. JDBC 연결 및 트랜잭션 유틸을 만든다.
2. H2 스키마 초기화를 구현한다.
3. 기본 상영 데이터와 고정 좌석 배치를 만든다.
4. 상영 정보를 저장/조회하는 repository를 구현한다.
5. 예매 정보를 저장/조회하는 repository를 구현한다.
6. `Main`에서 데이터베이스를 통해 상영 정보를 로드하고 예매를 저장하도록 연결한다.
7. 데이터베이스 연동 테스트를 작성한다.

### 6. 식별자 전략
- ID는 문자열 기반으로 관리한다.
- 의미 있는 식별자를 사용한다.
- 예:
  - 영화: `movie-f1`
  - 상영관: `screen-1`
  - 상영: `screening-movie-f1-screen-1-2025-09-20T10:20`
  - 예매: `reservation-screening-...-A1`
